# 티링크 케이스메이커
**설치 사진에서 확인한 장비를 근거로, 도입 상담에 쓸 웹 사례와 인스타그램 카드 3장을 만드는 AISH 스마트워크톤 MVP.**

[고객용 설치 가이드](https://tlink-installation-guide.hyunjun-j0003.workers.dev/) · [홍보 콘텐츠 스튜디오](https://tlink-installation-guide.hyunjun-j0003.workers.dev/studio)

## 심사위원 60초 체험 · 로그인과 API 키 필요 없음

1. **사진·마스크 검토.** [스튜디오](https://tlink-installation-guide.hyunjun-j0003.workers.dev/studio)의 **공식 사례 선택**에서 `은평***클럽 · 벽걸이 서버와 단자함`을 고른다. 사진 오른쪽의 미러링 스위치 또는 왼쪽의 벽걸이 서버를 선택하고, 설명이나 윤곽 꼭짓점을 수정한다. 공식 예시 선택 자체에는 AI 호출이 없다.
2. **홍보 콘텐츠 생성.** **검토 완료 · 홍보물 생성**을 누른다. **독립 HTML 저장**으로 받은 파일을 열면 사진의 장비 윤곽과 설명이 연결되고, 세 설치 방식의 3D 모형을 돌려볼 수 있다. **인스타그램 PNG 3장 ZIP**은 HTML 캡처가 아니라 질문 → 현장 사진 → 설치 방식·상담 순서로 편집한 별도 카드다.

**실제 AI 체험:** [공개 제조사 허브 사진](https://tlink-installation-guide.hyunjun-j0003.workers.dev/assets/rec-install-3.jpg)을 내려받아 스튜디오의 **사진 올리기**로 다시 올리면 장비 후보가 자동으로 생성된다. **작업 목록에 가져오기**를 눌러야 검토에 들어가며, 승인 전에는 결과물에 나가지 않는다. 승인 후 **카피 제안받기**는 승인된 설명만 보내는 별도 요청이다.

## 네 가지 심사 기준

| 기준 | 이 MVP가 보여주는 것 |
| --- | --- |
| **독창성** | 사진으로 바로 광고 문구를 만드는 대신, 사진에서 확인한 **위치·장비 윤곽**에 스탠드형·렉거치형·미러링스위치허브의 **공식 제품 설명**을 참고로 연결한다. 유형이 확실하지 않으면 보이는 배치만 설명한다. 담당자가 고친 설명과 윤곽만 웹 사례와 카드에 함께 쓰인다. |
| **실현가능성** | 공개 Cloudflare 주소에서 가이드·스튜디오 HTTP 200, 제조사 공개 사진 자동 분석과 승인 설명 카피 API의 실제 성공을 검증했다. Chrome에서 내보낸 HTML을 오프라인으로 열어 3D 모형 3개의 표시와 동작을 확인했고, ZIP의 PNG는 3장 모두 1080×1350이다. 키 없이도 공식 예시·수동 편집·내보내기를 체험할 수 있다. |
| **기획구체성** | 설치 사진 → 장비 후보 → 담당자 검토·승인 → 채널별 결과물로 이어진다. 공개 사진 **14장**에서 생성한 윤곽 후보를 대조해 **11장의 윤곽을 채택**하고 **3장은 기존 수동 윤곽을 유지**했다. 이는 편집 선택 건수이지 모델 정확도나 성능 지표가 아니다. 고객 가이드에는 설치 방식별 제조사 예시와 실제 현장 11장(스탠드 4·랙 5·허브 2)이 있다. 가이드와 결과물은 3D 모형과 사진 윤곽 표시 방식을 공유하지만, 스튜디오에서 승인해도 공개 갤러리를 바꾸거나 인스타그램에 게시하지 않는다. |
| **시장적합성** | 기업 통신 담당자의 “기존 랙을 그대로 쓸 수 있나요?”, “단자함 밖에 서버를 둘 수 있나요?” 같은 질문에 영업팀이 말뿐 아니라 사진과 구조로 답할 수 있게 한다. 다음 검증은 같은 사진으로 수동 제작과 비교해 **게시 가능한 두 결과물을 완성하는 데 걸린 시간**, **검토 중 수정 횟수**, **사례 페이지에서 상담 클릭 비율**을 측정하는 것이다. 시간 절감이나 전환 개선은 아직 측정하지 않았다. |

## 실행과 검증

```sh
npm start   # http://127.0.0.1:4173/ 또는 /studio
npm test    # Worker/Node 요청 일치, 승인 제외, 다각형, 비밀 접근 차단, 호출 상한
```

- **동작:** Node.js 22 이상 권장. 고객 가이드·공식 예시·수동 편집은 npm 의존성 설치 없이 쓸 수 있다. 3D는 드래그·휠 또는 화살표·+/−·Home으로 조작한다. 모형은 설치 방식을 보여주는 개념 모델로, 제조사 CAD·실측·배선도가 아니다. 고객 화면에는 편집 링크가 없다.
- **검증:** `scripts/install-qa.mjs`, `scripts/studio-v2-qa.mjs`는 Playwright Core와 Chrome으로 데스크톱·모바일 가이드, 모션 줄이기, 수동 작업, 모의 AI, 오프라인 HTML과 PNG ZIP을 확인한다. 실행 환경에 `PLAYWRIGHT_CORE`, `CHROME_PATH`를 설정한다(필요시 `QA_URL`). `scripts/worker-prod-qa.mjs`는 `TLINK_WORKER_URL`의 공개 배포에 실제 AI 요청을 보내므로 비용이 발생할 수 있다. 기본 `npm test`는 실제 OpenAI 호출을 하지 않는다.
- **호출 한도와 키:** 공개 데모의 AI 요청은 IP당 분당 **5회**, 전체 **UTC 하루 40회**다. 한도에 도달해도 공식 예시·편집·내보내기는 작동한다. 배포 키는 Cloudflare Workers Secret에만 저장한다. 로컬은 프로젝트 루트 `.env`의 `OPENAI_API_KEY` 또는 `API_KEY`를 서버만 읽는다. `.env`는 Git·HTTP 공개 대상이 아니다.
- **전송과 보관:** 파일을 올리면 리사이즈한 사진을 OpenAI Responses API로 보내므로 공개·전송 권한이 있는 사진만 사용한다. 사진 분석과 카피는 `gpt-6.2-astra`, `store:false`를 사용한다. 카피 제안에는 승인된 장비 설명과 편집 요청만 보낸다. 사진·좌표는 보내지 않는다. 앱은 원본 사진을 저장하지 않으며, 외부 API의 데이터 처리 정책까지 영구 미보관이라고 보장하지 않는다.
- **현장 윤곽 관리:** 고객 가이드는 정적 검토본을 사용해 모델을 부르지 않는다. 공개 원본만 다시 분석하려면 권한과 비용을 확인한 뒤 `node scripts/regenerate-masks.mjs --all`을 명시적으로 실행한다. `node scripts/review-masks.mjs --save-candidates`로 비교하고 직접 확인한 후보만 `--apply` 한다. 생성 파일, 원본 분석 로그, 과거 시안은 저장소에 포함하지 않는다.
