# 티링크 케이스메이커

AISH 스마트워크톤 MVP. 고객은 설치 환경의 선택지를 3D와 실제 사진으로 살펴보고, 마케팅 담당자는 사진에서 확인한 장비를 상담용 콘텐츠로 만든다. 인스타그램에 자동 게시하지 않는다.

## 웹 데모

- [고객용 설치 가이드](https://tlink-installation-guide.hyunjun-j0003.workers.dev/)
- [스튜디오](https://tlink-installation-guide.hyunjun-j0003.workers.dev/studio)
- Cloudflare Workers에서 공개 테스트용으로 실행한다. AI 요청은 IP당 분당 5회, 전체 일 40회(UTC)까지이며, 한도에 도달해도 공식 예시·수동 편집·다운로드는 사용할 수 있다. OpenAI 키는 Workers Secret에서만 읽는다.

## 로컬에서 실행

저장소를 내려받고 프로젝트 폴더에서 실행한다.

```sh
npm start
```

- 고객 가이드: **http://127.0.0.1:4173/**
- 스튜디오: **http://127.0.0.1:4173/studio**. 고객 화면에는 편집 링크가 없다.
- 고객 가이드와 수동 편집은 외부 연결이나 npm 의존성 설치가 필요 없다. 자동 이미지 분석에는 OpenAI 키와 인터넷 연결이 필요하다. Node.js 22 이상 권장.

## 고객 가이드

스탠드형·렉거치형·미러링스위치허브를 데스크톱 첫 화면에 나란히 보여준다. 세 제품 본체는 같은 오렌지색이다. 왼쪽 모델을 보면 파란 상태등이 있는 슬림 타워를 책상 위에 세운 모습을 확인할 수 있다. 모델은 로컬 Canvas에서 XYZ 형상과 원근으로 그리며, 제조사 CAD·실측·배선도가 아니다. 드래그는 회전, 휠은 줌이다. 화살표/+/-/Home으로도 조작할 수 있다.

각 설치 방식에는 **제조사 설치 예시가 먼저** 나오고, 실제 현장 사진은 아래 썸네일에서 선택한다(스탠드 4, 랙 5, 허브 2). 사진의 다각형은 제조사 공개 사진의 OpenAI 후보와 기존 수동 윤곽을 대조해 적절한 영역만 채택했다. 일치하지 않은 후보는 사용하지 않았다. 이를 클릭하거나 키보드 Enter를 눌러 설명을 확인할 수 있다. 제이*** 원본은 내려받을 수 없어 넣지 않았다. 짧은 화면 진입 전환을 제공하며 모션 줄이기 설정을 존중한다. 마우스와 키보드에서 사각형 기본 포커스 대신 장비 윤곽에 강조선을 표시한다. 스크롤을 강제하지 않는다.

## 스튜디오: 두 단계

1. **사진·마스크 검토.** 사진을 올리거나 공식 예시를 연다. 공식 예시의 윤곽은 사람이 표시한 것이며 AI 시연으로 표시하지 않는다. OpenAI가 설정된 경우 새로 올린 사진에 대해 분석이 자동으로 시작된다. 공식 예시를 고르는 것만으로는 API를 호출하지 않는다. 공개 권한이 있는 사진만 업로드한다. 후보는 ‘작업 목록에 가져오기’를 누르기 전까지 결과에 들어가지 않는다. 사진에서 직접 윤곽을 그리고, 꼭짓점/도형 드래그, 키보드(꼭짓점에서 화살표), 장비 이름·설명 수정, 삭제 및 실행 취소가 가능하다. 다각형이 교차하거나 설명이 비어 있으면 승인하지 않는다. 같은 탭에서 사진을 다시 선택하면 편집 데이터만 복원한다. 사진 파일은 저장하지 않는다.
2. **홍보 콘텐츠 생성.** 검토 완료와 동시에 승인한 장비를 사용한 결과물이 열린다. 관심사와 편집 요청을 바꿔 다시 생성할 수 있다. 고객용 독립 HTML은 사진, 클릭 가능한 마스크와 세 가지 설치 유형의 인터랙티브 3D 모형을 내장하고 오프라인에서 열린다. 인스타그램 파일은 HTML 캡처가 아닌 별도 1080×1350 PNG 3장(질문, 실제 현장 사진, 세 설치 유형의 정적 3D 렌더·상담)을 ZIP으로 저장한다. 미승인 후보와 내부 상태는 결과물에 나가지 않는다.

### 선택: OpenAI 연결

프로젝트 루트 `.env`의 `OPENAI_API_KEY` 또는 `API_KEY`를 서버만 읽는다. `.env`는 Git 제외 상태이고 HTTP로 서빙하지 않는다. 브라우저 폼·채팅·소스에 키를 붙여 넣지 않는다. 키가 없으면 수동 편집과 공식 예시를 사용할 수 있다.

**사진은 업로드와 함께 자동 분석된다.** 화면에 안내된 것처럼 리사이즈한 사진을 OpenAI Responses API에 전송하고 위치와 설명 후보를 받는다. 모델에 스탠드형·렉거치형·미러링스위치허브의 공식 설명을 참고로 제공한다. 고객 문구는 사진에서 보이는 배치를 먼저 설명하고, 근거가 부족하면 유형을 단정하지 않는다. 후보를 가리키거나 키보드로 고르면 사진 위 점선 미리보기가 나온다. 마케팅 카피 제안 버튼은 별도 요청이며 승인한 장비 설명과 편집 요청만 전송하고 사진·좌표는 보내지 않는다. 모델은 `gpt-6.2-astra`; 요청에는 `store:false`를 사용한다. 외부 API의 데이터 처리 정책까지 영구 미보관이라고 보장하지 않으며 비용이 발생할 수 있다. 검증에는 티링크 공개 갤러리·제조사 사진만 사용했다.

## 시연과 검증

- 가이드에서 랙 회전·줌 → 제조사 예시 → 실제 사진 썸네일과 마스크 → 직접 `/studio` → 공식 사례 선택 또는 사진 업로드 → 장비 윤곽/설명 수정 → 승인 → HTML·카드 미리보기/저장.
- `npm test`: 다각형 유효성, 11개 사례의 분류별 수, 미승인 제외, 명시 동의/키 검사, OpenAI 모의 응답과 고객 산출물.
- `scripts/install-qa.mjs`, `scripts/studio-v2-qa.mjs`: 앱 실행 후 Playwright Core와 Chrome이 있을 때 실행한다(`PLAYWRIGHT_CORE`, `CHROME_PATH`, 선택적으로 `QA_URL`). 고객 가이드는 데스크톱·모바일 및 모션 줄이기, 스튜디오는 수동 작업·키 없는 실행·모의 OpenAI·오프라인 HTML·PNG ZIP을 검사한다. `LIVE_PUBLIC=1`로 실행한 실측 테스트는 승인된 사례 08 공개 사진 1장만 업로드하며 비용이 발생할 수 있다(기본 테스트엔 없음).
- 결과물은 스튜디오에서 생성해 다운로드한다. 생성 파일과 원본 분석 로그, 과거 시안은 저장소에 포함하지 않는다.

원본 공개 사진만 대상으로 후보를 다시 생성해야 할 때는 비용과 권한을 확인한 뒤 `node scripts/regenerate-masks.mjs --all`을 명시적으로 실행한다. 정적 고객 페이지에서는 모델을 부르지 않는다. 후보 비교는 `node scripts/review-masks.mjs --save-candidates` 후 브라우저로 확인하고, 검토한 ID만 `--apply` 한다.
